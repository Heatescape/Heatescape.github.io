01

Portal update automation platform

In production

Python, FastAPI, Azure SQL, Azure Blob Storage, Dropbox API, scheduled unattended operation, web dashboard.

A five stage ETL pipeline, collect, extract, match, publish, notify, that ingests developer price lists and floor plans from heterogeneous channels including Dropbox, Box, Gmail and custom web portals, then publishes to the company's live public property portal. Roughly 30 developer file formats. The dashboard gives staff manual control, live monitoring and a human review queue.

  • Hybrid rule based and LLM document extraction. The extraction engine handles 80 to 90 column name variations across developer formats, with a Gemini backed fallback for PDFs that rule based parsing cannot read. It auto detects property type, apartment, townhouse, house and land, land only, and applies type specific field mapping.
  • Multi source data reconciliation. I reconciled pricing and availability across four disconnected sources: the authoritative price list, marketing floorplates, archived files and the live public portal. It surfaced data quality problems nobody had reported, including seven units carrying the price of a different building, and sold stock still publicly listed. The real insight was that the drift came from system handoffs, not from careless data entry, so the fix was a scheduled reconciliation rather than a one off cleanup.
  • Verified line by line. The first source taken fully to production was confirmed record by record against the live portal rather than in dry run.

02

Agentic AI voice assistant, in the company CRM

Feature complete, pending compliance sign off

ASP.NET Core 8, .NET MAUI (Android), Google Gemini 2.5 Flash, Azure SQL, JWT authentication.

Sales agents speak or type a question in English, Chinese or a mix of both, and the assistant either answers it or files the follow up note against the client record. It covers property search, affordability and loan calculations, and client log updates in one chat surface on the mobile app, replacing thumb typing in the field and switching between five separate screens. It is feature complete, pending compliance sign off and production authentication cutover.

  • A tool calling agent, not similarity search. For a sales tool quoting prices and availability, similarity is the wrong primitive. The data has to be exact and live, so the model picks the tool and fills the parameters, and SQL does the rest.
  • Intent recognition and slot filling. The language model turns natural language into typed search criteria, then selects from roughly 12 deterministic tools that query Azure SQL. The model never generates a figure itself. Speech to text runs multimodal through Gemini with schema constrained output.
  • Bilingual by design. English, Chinese, or a mix of both inside the same sentence.

How I ship safely

Publishing to a public property portal means a bad write is visible to customers.

So the controls came first, and they are the part of the work I would want reviewed hardest.

Traceability

Audit logging on every write to live data

Every write to live data is recorded to an audit log and remains traceable after the fact.

Human in the loop

Risk based approval routing

Actions are routed by risk. Low risk publishes automatically. High risk goes to a human review queue.

Concurrency safety

A guard that re validates the source before writing

An approval given against a stale preview is rejected rather than published. That control caught and blocked a real stale write incident in production.

Confidentiality

Sensitive commission data filtering

Confidential commission figures are kept off the public portal, alongside versioned compliance archiving of every published price list.

Privilege separation

The model is kept out of the permission layer

In the CRM assistant, the identity used for a query is set by the authenticated session and can never be supplied by the model, so it cannot query on behalf of another user.

Bounded agency

A capped agent loop with full tool call tracing

The agent loop is bounded to a maximum of 6 tool calls. Every tool call is traced with its arguments and a result summary for after the fact review.

Anti hallucination

A faithfulness constraint in the data contract

The assistant must state when no option matches the buyer's budget before listing near misses, rather than relying on prompt instructions to keep it honest.

Regression testing

206 automated test files on the portal platform

Including regression suites built from real sample PDFs, so a new developer format cannot quietly break an old one.
